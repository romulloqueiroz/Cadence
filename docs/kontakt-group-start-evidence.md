# Kontakt group-start, key-switch and controller evidence

Static investigation summarised 2026-11-07 for Cadence's independent group
selection. The full pedal/sustain trace, CC64 encoding and file digests are in
[kontakt-pedal-release-evidence.md](kontakt-pedal-release-evidence.md); zone fade
gains are in [kontakt-crossfade-evidence.md](kontakt-crossfade-evidence.md).

## Artifact and observation boundary

Target: the saved REA/Ghidra export of Kontakt 8.14.1's ARM64 main executable
under `../../Kontakt-8-REA/`. The decisive behavior is generated by
`BEngine::GenerateSysScript` (`0x1003d418c.c`), which emits the system KSP
scripts run by note, release and controller callbacks. That is why tracing only
`NoteOn`/`NoteOff` misses group start and pedal behavior.

No Kontakt process was launched and no saved analysis was changed. Pseudocode is
provider output, not original source.

## Observed behavior

| Behavior | Saved location | Observation |
| --- | --- | --- |
| Round robin | `0x1003d418c.c`, lines 421-428, 723-731 | One shared counter starts at -1 and increments modulo `max(configured cycle class)+1` on ordinary note callbacks. It does not advance for synthetic release-trigger notes, so a release layer uses the current instrument counter rather than its attack's old value. |
| Random | `0x1003d418c.c`, lines 428-429, 734-738 | One shared random index is chosen from `0..numRandom-1` per note callback, where `numRandom` counts random criteria entries. The draw has no release-trigger guard, unlike round robin. |
| Criterion connectors | `0x1003d418c.c`, lines 751-894 | Criteria are emitted as parenthesised predicates in one flat expression using `and`, `and not` or `or`; no additional grouping is introduced. Connector strings establish emitted syntax, not KSP parser precedence. |
| Key-switch latch | `0x1003d418c.c`, lines 679-717 | Non-polyphonic `$keySelectRange_N` variables are set during init and updated on note callbacks; they are not cleared by release. This is a shared instrument-wide latch, not a held-key test or per-channel state. |
| Key-switch bounds | `0x1003d418c.c`, lines 683-717 | A note inside `min(low)..max(high)` clears all flags and then sets every interval containing it. A gap inside that bounding interval clears every flag; a note outside preserves the previous selection. Overlapping intervals may both be selected. |
| Default key switch | `0x1003f7b04.c`; original instructions `0x1003d4f2c..0x1003d4f60` | A negative stored default selects the lowest configured key criterion's low bound. Each range flag starts from inclusive membership of that key. |
| Raw note for selection | `0x1003d418c.c`, lines 679-717; `0x1003e9418.c`, lines 275-310 | Key selection runs before instrument/zone key-range selection and therefore sees the input note before transpose. |
| Controller state | `0x100774120.c` | CC values are channel-addressed at `state + channel*0x200 + cc*4`. |
| CC64 sustain | `0x1003d418c.c`, lines 435-455 | At `%CC[64] >= 64` a note-off is marked and ignored; when CC64 falls below 64 the marked releases are replayed. Still-held keys are not released on pedal-up. |
| Release layers | `0x1003d418c.c`, lines 582-645 | The release-layer callback exits while the damping pedal is down; otherwise it starts one synthetic note carrying the original attack velocity. |
| CC120/123 | `0x1003d418c.c`, lines 1107-1111 | When enabled, CC120 fades and stops all events; CC123 requests note-off for all events. The setting defaults enabled. |

## Cadence implementation

`crates/sample-adapter/src/group_start.rs` keeps the instrument-wide selection
state:

- Round-robin counter and modality from the largest `cycleClass`.
- A single deterministic random ordinal per note; a small xorshift generator is
  used and `SamplerPlugin::seed_random` exposes a repeatable seed.
- Latched key-switch flags derived from the program default key.
- Per-channel 128-entry controller banks.
- A left-to-right fold of criteria using the previous criterion's connector.

`SamplerPlugin` applies the state as follows:

- Release groups are identified by the serialized `release_trigger` flag only.
  This matches `GenerateSysScript`, which builds `%rlsTrigGroups` from runtime
  `+0x65b`. The earlier binary display-name heuristic was wrong for the
  installed Piano Uno Concert preset, whose "Release" group has the flag clear.
- Every note-on advances round robin and updates the key-switch latch before zone
  selection. Release-layer spawning draws a fresh random ordinal but does not
  advance round robin or the key latch.
- `spawn` checks the group's start conditions, applies the program range gates,
  and multiplies the recovered zone fade gain once per voice.
- Sustain-pedal note-offs mark matching voices as deferred instead of releasing.
  Pedal-up releases those voices and then starts release layers with the stored
  attack velocity.
- `cc64_mode_controller_only` disables the system pedal path, leaving CC64 only
  as an ordinary controller criterion.

Audio regressions live in
`crates/sample-adapter/tests/group_selection.rs` and cover round-robin cycling,
seeded random one-of-N selection, default and latched key switches, controller
criteria and connectors, sustain deferral, release-layer pedal gating and
controller-only CC64. Run them with:

```sh
cargo test -p sample-adapter --test group_selection --offline
```

## Limits

- Connector precedence is a deterministic left-to-right Cadence policy; the
  decompiled strings do not prove KSP parser precedence.
- Random selection is one shared instrument-wide draw, per the recovered system
  script. It is not per-group or per-channel.
- The effect of CC120's native 10 ms fade on synthetic release layers was not
  traced; Cadence uses an immediate panic.
- CC121 reset-controllers, exact power-on controller defaults, and script-driven
  group routing are not emulated.
- Large-library and DAW session validation remains deferred.
